// install — 60 seconds

From nothing to a live preview.

No YAML novels. No secret juggling. The shipped docker-compose.yml runs with OXID_AUTO_TOKEN=1 — secrets generate themselves, persist under /data, and the dashboard's onboarding wizard does the rest.

01 — run

docker compose up -d

Or one line from nothing — verifies checksums, generates OXID_API_TOKEN + WEBHOOK_SECRET (0600, never rotated on re-run), pulls ghcr.io/sazardev/oxid, starts daemon + Traefik, waits for health.

$ curl -fsSL https://raw.githubusercontent.com/sazardev/oxid/main/install.sh | sh -s -- --docker
[+] Dashboard: http://localhost:8080  → wizard
# or manually:
$ docker compose up -d
$ docker compose logs oxid-daemon | grep -A2 Generated  # your token, printed once
02 — wizard

Open the dashboard

First visit auto-opens /ui/onboarding — five steps, everything also available later via CLI:

  1. Token — paste OXID_API_TOKEN (or grab it from docker compose logs)
  2. Infrastructure — one-click bootstrap of Docker network + Traefik
  3. First project — register by Git URL (private repos take an encrypted PAT) or /repos path
  4. Webhooks — copy URL + auto-generated secret into your Git host
  5. CLI — copy-paste oxid context add … snippet

Prefer the terminal? oxid up main --repo https://github.com/you/app.git

03 — push

Push a branch

Every push deploys itself. Delete the branch, the environment disappears. Zero-downtime cutover every time.

$ git push origin feature-carrito
[>] Building image (cache hit: 85%) ...
[+] https://feature-carrito.local.dev  (or :port in direct mode)

$ oxid status        # live URLs + ports
$ oxid logs -f feature-carrito

Traefik mode = stable branch.base-domain subdomains + wake-on-request scale-to-zero. Direct-publish mode works too — each env gets its own host port, no DNS needed. Full reference: Install guide · Daemon env vars · Quickstart.

// why

Staging environments shouldn't cost like production ones.

The problem

A preview environment per feature branch usually means one of two things: paying a cloud platform for staging instances that sleep 90% of the time, or drowning your local server (or NAS) in Docker containers nobody remembers to stop.

The Oxid way

Oxid detects a push, injects secrets, deploys the container, connects it to a proxy — and if nobody visits it in 30 minutes, it pauses in memory. The next visit wakes it in milliseconds. Vercel-style preview URLs, at the resource cost of a calculator.

// what it offers

Opinionated, so you don't have to configure it.

Zero friction

No YAML novels. If there's a Dockerfile, Oxid knows what to do. Drop an oxid.toml when you want more control.

Real scale-to-zero

Idle branches get paused in memory, not just billed differently. First request wakes the container and serves you like nothing happened.

Resource multiplexing

One shared Postgres, one shared Redis — dozens of branches, one logical database each. No cluster sprawl for ephemeral data.

Fully local, fully audited

No external database required. Every deploy, log line, and injected variable is recorded in an embedded, transactional SQLite.

One control plane, many surfaces

CLI, TUI, web dashboard and a lightweight desktop app all talk to the same daemon — pick whichever fits the moment.

Written in Rust

A single static binary, minimal memory footprint, unsafe forbidden workspace-wide. Built to sit quietly on hardware you already own.

// the golden path

You never feel the machinery.

  1. 01

    Install — one command

    curl .../install.sh | sh -s -- --docker or docker compose up -d. Secrets generate themselves (OXID_AUTO_TOKEN), persist under /data, printed once.

  2. 02

    Wizard — five clicks

    Open http://localhost:8080 → token → one-click infra bootstrap → register by Git URL (or /repos path). First deploy kicks off for you.

  3. 03

    Push a branch

    git push origin feature-carrito — that's the entire interface from then on. Webhook → clone → build → deploy. Proxy routes feature-carrito.local.dev automatically.

  4. 04

    Breathe

    No traffic for a while? Oxid pauses it and gives the RAM back. A tester opens the URL — it wakes in milliseconds. Delete the branch, the environment disappears.

deploy

The push button, plus an undo.

  • oxid up <branch>
  • oxid rollback [--to <sha>]
  • oxid pause / wake
  • oxid down · rm-project

observe

What's live, what it's doing, what happened.

  • oxid status --sort --filter
  • oxid logs -f — live stream
  • oxid audit --since --kind
  • oxid ps · queue

secrets & policy

Scoped variables, lifetimes, many daemons.

  • oxid env set K=V --scope branch
  • oxid configure --pause-after 30m
  • oxid context add staging --api ...
  • oxid env list / delete

operate

Day-2 care, built in from day one.

  • oxid doctor
  • oxid backup / restore
  • oxid rotate-key · token
  • oxid infra setup

Every command speaks --json with distinct exit codes for CI pipelines, and your shell gets tab completion via oxid completions zsh.

// status

Ready to run. Honest about what's next.

Oxid already runs end to end in production topology: one-command Docker install (OXID_AUTO_TOKEN generates and persists secrets for you), a five-step onboarding wizard that registers your first project straight from a Git URL — no shared filesystem — webhook ingestion, secret injection, container orchestration, scale-to-zero garbage collection and zero-downtime redeploys. The embedded web dashboard and the CLI cover the full lifecycle: deploy and roll back, live-stream logs, scope secrets per branch, manage multiple daemons as contexts, back up and restore state, rotate the encryption key with zero downtime. The TUI and desktop app described below are still part of the plan — the ROADMAP tracks exactly what's real today versus what's still ahead, line by line.
